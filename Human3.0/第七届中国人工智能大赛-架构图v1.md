## 二、分层说明（申报书可直接引用）

| 层 | 组件 | 职责 | 对应评审维度 |
|---|---|---|---|
| L1 交互层 | 前端演示界面 | 上传材料、选文种、一键生成、人工修订、导出 | 演示与答辩10 |
| L2 智能层 | Agent 工作流（①→⑥） | 六步编排：识别→检索→起草→校验→自查→导出 | 技术创新20 |
| L3 知识层 | RAG 向量库 | 模板库/政策库/历史样例检索增强 | 技术方案25 |
| L3 规则层 | 规则引擎 | 格式硬校验 + 合规自查（独立于模型，可审计） | 技术方案25+场景适配25 |
| L4 模型层 | 大模型推理引擎 | 私有化部署/API，数据不出域 | 应用成效20 |

## 三、创新点标注（申报书"技术创新"章节素材）

1. **格式即规则**：GB/T 9704 要素级硬校验（标题/主送/正文/落款/日期），独立于模型输出——通用大模型工具缺失的能力
2. **合规前置**：敏感表述/涉密提醒进入生成链路（⑤在⑥之前），不是事后过滤
3. **私有化=合规**：L4 数据不出域架构，正面回应"政务信息安全合规底线"（评审硬指标）

## 四、数据流（一句话讲给评委听）

> 办文员上传零散材料 → 系统识别文种并检索本单位规范库 → 起草符合格式的初稿 → 机器校验格式与合规 → 一键导出规范公文。**全程材料不离开单位内部部署环境。**

## 五、技术选型基线（后续实现按此，不引入新体系）

| 组件 | 方案 | 说明 |
|---|---|---|
| 前端 | Streamlit / FastAPI+HTML | 演示优先，FastAPI 更"工程" |
| Agent | LangGraph 或自写状态机 | 你已有经验，先能跑再优化 |
| RAG | 本地向量库（Chroma 起步） | 轻量，不引入大集群 |
| 模型 | 本地部署或 API（数据不出域方案写清） | 视算力定 |
| 导出 | python-docx | 生成标准公文格式 |
