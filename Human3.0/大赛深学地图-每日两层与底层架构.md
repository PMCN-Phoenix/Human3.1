## 二、底层架构主线（看穿全作品的黑盒）

```
用户零散材料
   │ ①解析（docx/pdf→纯文本，保留结构）
   ▼
分块（按公文结构切：标题/主送/正文/落款，而非固定字数）
   │ ②嵌入（句向量模型把文本变高维向量）
   ▼
向量检索（HNSW近似最近邻，语义相似召回Top-K）
   │ ③BM25关键词召回（"请示""经费"这类强信号词兜底）
   ▼
重排（RRF融合 或 交叉编码器精排，取最终上下文）
   │ ④上下文组装（检索片段+任务指令→LLM输入）
   ▼
LLM生成初稿（ReAct/工具调用：文种识别→起草）
   │ ⑤规则引擎校验（GB/T9704要素级：标题/主送/正文/落款/日期/版记）
   ▼
合规自查（敏感词/涉密/规范表述，⑤在⑥前=合规前置）
   │ ⑥python-docx 生成标准公文
   ▼
导出 .docx（数据全程不出域）
```

**每个环节的L2原理点**（按深学优先级排序）：
1. **分块>检索**：政务公文按结构分块（段落/条款）远胜固定字数——这是你的差异化，也是RAG工程公认最影响效果的一环
2. **混合检索**：向量管语义、BM25管强信号词，RRF融合——2026主流做法
3. **确定性引擎边界**：格式校验必须确定性规则（不靠LLM），LLM只负责生成与识别——"格式即规则"创新点
4. **可审计性**：每步状态落盘、可回放——LangGraph checkpoint 一等公民能力，也是政务评审"可信"的关键
